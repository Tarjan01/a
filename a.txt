# 目标域调优任务书

## 背景

- 源域：`rearranged_train`（HumanRefiner，约 50,459 张）
- 目标域：`huawei_data`，训练/测试各几百张（1:1 切分），已确认非评估噪声
- 当前方法：`domain_fine_tuning.py`（30% 源域 + 70% 目标域混采，冻结 backbone 5 epoch 后解冻全量微调）
- 现状指标：目标域 Acc/Recall 均卡在 ~70%，基础要求为 Acc≥80%，Recall≥85%
- 目标：在不新增大量标注数据的前提下，把当前微调策略换成更适合小样本目标域的方案

**优先级顺序：任务1 → 任务2 → 任务3 → 任务4 → 任务5**（前面成本低、验证快，建议按序执行并记录每一步的目标域 Acc/Recall/Precision，不要跳步）

---

## 任务 1：阈值重搜 + TTA（零训练成本，先做这个）

### 1.1 目标域最优阈值搜索

**问题**：当前二分类阈值硬编码为 0.5，这是在源域上校准的，目标域分布不同，大概率不是最优阈值。

**实现要求**：
1. 新建脚本 `threshold_search.py`
2. 加载已经 finetune 好的模型（`cross_domain_fine_tuned.pth`），在目标域**验证集**（不是测试集）上跑一遍推理，保存所有样本的 `binary_logit`（sigmoid 后的概率）和真实标签
3. 对阈值从 0.05 到 0.95，步长 0.01 做网格搜索，每个阈值计算 Acc / Recall / Precision / F1
4. 由于业务要求 Recall ≥ 0.85，搜索时先过滤出所有满足 Recall ≥ 0.85 的阈值候选，再从中选 Acc 最高的一个（如果没有候选满足 Recall≥0.85，选 Recall 最大化的阈值并输出警告）
5. 将最优阈值保存到 `models_parameter/finetuned/best_threshold.json`，格式：`{"threshold": 0.xx, "val_acc": 0.xx, "val_recall": 0.xx}`
6. 多标签的 8 类异常分类头也做同样的每类别独立阈值搜索（8 个阈值），因为不同异常类别在目标域上的分布可能差异很大

**验证**：用搜出来的阈值在目标域**测试集**上跑一遍，对比默认 0.5 阈值下的指标提升。

### 1.2 测试时增强（TTA）

**实现要求**：
1. 在推理脚本中新增 `--tta` 开关
2. 对每张测试图片生成 3 个增强版本：原图、水平翻转、轻微旋转（±3度）
3. 对应的骨架热力图也要做同样的翻转/旋转变换（复用 `sk_dataset.py` 中 `JointTransform` 里已有的翻转/旋转逻辑，抽出来做成独立可调用函数 `apply_geometric_transform(image, skeleton, hand_skeleton, mode)`）
4. 3 个版本分别过模型，对 `binary_logit` 和 `multi_logits` 的 sigmoid 概率取平均，作为最终预测
5. 输出 TTA 前后的指标对比表

## 任务 2：AdaBN（只重算 BN 统计量，不训练任何权重）

**目的**：验证"过拟合假设"——如果只做分布对齐就能大幅提升，说明当前全量微调确实在小数据上过拟合。

**实现要求**：
1. 新建脚本 `adabn_calibration.py`
2. 加载**源域预训练好、未经过 domain_fine_tuning 的原始模型**（`best_model_ema_opt.pth`，注意不是已经 finetune 过的版本，避免和后续实验混淆）
3. 将模型中所有 `nn.BatchNorm2d` 层设置为训练模式（`.train()`），但其余所有层（包括 backbone 的 conv 权重、cross-attention、分类头）全部 `requires_grad_(False)` 并设为 `.eval()`
4. 用目标域**训练集**（几百张）以较小 batch size（如 16）多次前向传播（不需要反向传播，不需要 loss，只是让 BN 层的 `running_mean`/`running_var` 在目标域数据分布下重新累积），建议跑 3-5 个 epoch 的"伪训练"（实际只更新 BN running stats）
5. 保存校准后的模型为 `models_parameter/finetuned/adabn_calibrated.pth`
6. 在目标域测试集上评估，和任务 1 的结果对比

**如果 AdaBN 后指标显著提升（比如到 78-80%+），说明后续应该往"减少可训练参数"方向走（任务3）；如果提升有限，说明问题更多在特征判别力不足，应该往任务4（域对齐损失）或数据增强方向走。**

---

## 任务 3：只调分类头 / Head-only Tuning + Adapter

### 3.1 纯 Head-only 微调（对照实验）

**实现要求**：
1. 复用现有 `DomainFineTuner`，新增参数 `freeze_mode`，可选 `"full"`（当前行为）/ `"head_only"` / `"adapter"`
2. `head_only` 模式：冻结 backbone（Stem + 4 个 Stage）+ cross-attention 注入模块（`attn2`/`attn3`）的全部参数；只训练 `neck_projector`、`fusion_weights`、`combined_multi_classifier`、`combined_binary_classifier`、`SpatialAttention`、`PatchAnomalyHead`（S3/S4）
3. 学习率可以适当调高（因为参数量小了很多），建议 `head_lr=1e-4`，其余保持默认 `3e-5`（其实全冻结后只有 head 在训练，直接用一个学习率即可）
4. 训练 15-20 epoch（不需要像全量微调那样谨慎），batch size 可以适当调大（32-64），因为可训练参数量骤减，过拟合风险降低
5. 加大 dropout：`neck_projector` 中的 dropout 从 0.4 提到 0.5-0.6（因为目标域数据少，head 部分需要更强正则化）

### 3.2 轻量 Adapter（如果 head_only 效果不够，再做这个）

**实现要求**：
1. 在每个 ConvNeXt Stage 输出后插入一个轻量 bottleneck adapter：`Conv2d(C, C//4, 1) → GELU → Conv2d(C//4, C, 1)`，输出通过残差连接叠加：`x = x + adapter(x)`，adapter 权重初始化接近 0（最后一层 conv 权重初始化为 0，保证初始时 adapter 不改变原始特征，训练稳定）
2. 训练时只解冻：4 个 adapter + cross-attention 模块的 `gamma` 参数（不解冻 Q/K/V 卷积权重，只解冻 gamma 这个标量）+ 所有分类头/融合层
3. 这样可训练参数量远小于 head_only 方案里的全部融合层，但比纯 head_only 有更强的特征适配能力
4. 保存为独立 checkpoint，与 3.1 的结果对比

**产出要求**：一张对比表，行为 [Full Finetune（当前基线）/ AdaBN / Head-only / Head+Adapter]，列为 [目标域测试集 Acc/Recall/Precision/F1，可训练参数量占比]

## 任务 4：域对齐损失（CORAL）

**目的**：显式约束源域和目标域在特征空间的分布对齐，而不是仅靠混合采样隐式对齐。

**实现要求**：
1. 在 `DomainFineTuner.fine_tune` 的训练循环里，每个 batch 同时前向源域和目标域数据（当前代码结构已经是分别采样源域和目标域 batch，直接复用）
2. 提取两者的 `neck_projector` 输出（768维融合特征，在 `final_norm` 之前或之后均可，建议用 `final_norm` 之后的版本，更稳定）
3. 实现 CORAL Loss：

```python
def coral_loss(source_feat, target_feat):
    """
    source_feat: [B_s, D], target_feat: [B_t, D]
    对齐两者特征的二阶统计量（协方差矩阵）
    """
    d = source_feat.size(1)
    source_feat = source_feat - source_feat.mean(dim=0, keepdim=True)
    target_feat = target_feat - target_feat.mean(dim=0, keepdim=True)
    cov_s = (source_feat.t() @ source_feat) / (source_feat.size(0) - 1)
    cov_t = (target_feat.t() @ target_feat) / (target_feat.size(0) - 1)
    loss = torch.sum((cov_s - cov_t) ** 2) / (4 * d * d)
    return loss
```

4. 总损失改为：

```python
total_loss = 1.0 * loss_multi + 5.0 * loss_binary + lambda_coral * coral_loss(source_feat, target_feat)
```

5. `lambda_coral` 建议从 0.1 开始做网格搜索（候选：0.01, 0.05, 0.1, 0.5, 1.0），过大会导致目标域任务本身的判别损失被压制
6. 注意 CORAL 对 batch size 敏感（协方差矩阵在小 batch 下估计不准），确保源域和目标域每个 batch 至少各有 16-32 个样本，如果目标域 batch 太小考虑用**滑动窗口累积特征**（缓存最近 N 个 batch 的目标域特征再算协方差）而不是单 batch 计算
7. 建议在 `head_only` 或 `adapter` 微调模式的基础上叠加 CORAL loss（而不是在全量微调基础上），组合验证

**产出要求**：加入 CORAL loss 前后的指标对比，以及不同 `lambda_coral` 取值的敏感性分析（表格即可，3-5 组）

## 任务 5：目标域专属统计量重新校准

**实现要求**（成本低，可以和上述任意任务并行做）：
1. 新建函数 `compute_target_pos_weights(target_dataset)`，单独统计目标域训练集的 8 类异常正负样本比例，按现有公式重新计算 `pos_weights`（不要复用源域统计的 `pos_weights`）
2. 微调阶段的 `FocalLoss` 改为使用目标域专属 `pos_weights`
3. 微调阶段 `FocalLoss` 的 `gamma` 从 2.5 降到 2.0（目标域样本少，过强聚焦容易在极少数难样本上震荡，导致训练不稳定）
4. 如果目标域某些异常类别（1-8类中的某几类）样本数极少（比如个位数），在训练时对这几类适当降低该类别在多标签 loss 中的权重贡献，或考虑该类别单独用之前源域的分类边界，不参与目标域头部微调（避免极端小样本导致该类别决策边界被少数几个样本带偏）
